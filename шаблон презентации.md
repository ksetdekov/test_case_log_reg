Слайд 1: Титульный слайд
Название: Анализ и прогнозирование блокировок расчетных счетов на основе данных по заявкам
(Опционально): Автор / Дата
Слайд 2: Цель проекта
Основная задача: Разработка модели для прогнозирования вероятности блокировки расчетного счета клиента в течение 6 месяцев после даты подачи заявки.
Дополнительная задача: Оценка влияния различных групп признаков на качество прогноза модели.
Слайд 3: Обзор используемых данных
Заявки (Заявки.xlsx): Информация о заявках клиентов, включая ID заявки, ИНН, дату заявки и тип организации.
Открытые РС (Открытые рс.xlsx): Данные по открытым расчетным счетам: ИНН, дата открытия и дата закрытия счета.
Блокировки (Блокировки.xlsx): Информация о фактах блокировок счетов с указанием ИНН и даты блокировки.
Наличие кредитного продукта (Наличие_кредитного_продукта.xlsx): Данные о наличии у ИНН других кредитных продуктов.
Спарк (спарк.csv): Внешние данные по компаниям из системы "Спарк".
Слайд 4: Ключевые выводы EDA - Динамика заявок
График: "Количество заявок по месяцам в разрезе по типу организации".
Наблюдения:
Выявлена сезонность в количестве подаваемых заявок.
Динамика количества заявок от Индивидуальных Предпринимателей (ИП) и Юридических Лиц (ЮЛ) может различаться в разные периоды времени.
Слайд 5: Ключевые выводы EDA - Анализ ИНН и открытых счетов
Множественные заявки: Установлено, что существуют ИНН с несколькими заявками на открытие счета.
Несколько открытых счетов: Около 1% ИНН имеют более одного открытого счета с различными датами открытия.
Слайд 6: Определение целевой переменной (Target)
Целевое событие: Блокировка расчетного счета клиента.
Определение:
Target = 1: Если счет клиента был заблокирован в течение 6 месяцев после даты подачи заявки.
Target = 0: Если блокировки в указанный период не произошло.
Слайд 7: EDA - Динамика целевой переменной
График: "Динамика таргета (доли блокировок) по месяцам в разрезе по типу организации".
Наблюдения:
Доля блокировок (целевая переменная) также демонстрирует сезонные колебания.
Динамика блокировок может отличаться для ИП и ЮЛ.
Проблема сезонности: Менее двух лет данных затрудняет учет сезонности стандартными методами, такими как скользящее среднее.
Слайд 8: Конструирование признаков (Feature Engineering) - Часть 1
Заявки до даты: Порядковый номер текущей заявки для каждого ИНН (фактически, количество предыдущих заявок от того же ИНН).
Гистограмма распределения этого признака показывает, что большинство заявок являются первыми для клиента.
Продукт открыт ранее: Бинарный признак, указывающий, был ли у данного ИНН открыт расчетный счет до даты текущей заявки (1 - да, 0 - нет).
Примерно 23.6% заявок поступают от клиентов, у которых уже был открыт продукт ранее.
Продукт ранее закрыт: Бинарный признак, указывающий, был ли у данного ИНН закрыт счет до даты текущей заявки (1 - да, 0 - нет).
Примерно у 1% заявок был ранее закрытый продукт.
Слайд 9: Конструирование признаков (Feature Engineering) - Часть 2
has_products: Бинарный признак наличия любого другого кредитного продукта у клиента (на основе файла Наличие_кредитного_продукта.xlsx) (1 - да, 0 - нет).
Примерно 3.6% заявок имеют другие кредитные продукты.
Календарные признаки (из даты заявки):
month: Месяц подачи заявки.
weekday: День недели подачи заявки.
hour: Час подачи заявки.
Тип организации_ЮЛ: Бинарный признак (1 для ЮЛ, 0 для ИП), полученный путем One-Hot Encoding.
Слайд 10: Подходы к моделированию и результаты
Метрика качества: Gini.
Подход 1:
Описание: Использование только исходных признаков заявки (Тип организации, has_products, Продукт открыт ранее, Продукт ранее закрыт, Заявки до даты).
Gini = 0.21
Подход 2:
Описание: К признакам из Подхода 1 добавлены календарные признаки (month, weekday, hour).
Gini = 0.22
Подход 3 (Лучшая модель):
Описание: Использование всех признаков из всех файлов (включая данные "Спарк") после одномерного отбора, применения PCA, добавления агрегированных признаков и отбора признаков методом RFECV на кросс-валидации.
Gini = 0.32
Слайд 11: Основные выводы
Лучшая модель: Наивысшее качество прогнозирования (Gini = 0.32) было достигнуто при использовании комплексного подхода, включающего все доступные данные (в том числе внешние из "Спарк"), агрегированные признаки и продвинутые техники отбора признаков (PCA, RFECV).
Влияние календарных признаков: Простое добавление календарных признаков к базовому набору параметров заявки дало лишь незначительное улучшение Gini (с 0.21 до 0.22).
Базовая модель: Использование только основных параметров заявки (без данных "Спарк" и сложных преобразований) показало Gini на уровне 0.21.
Сезонность: Данные по заявкам и блокировкам имеют выраженную сезонность, что необходимо учитывать при моделировании.
Слайд 12: Возможные направления для дальнейшей работы
Углубленный анализ данных "Спарк": Детальное изучение и использование признаков из файла спарк.csv, так как они внесли наибольший вклад в лучшую модель.
Развитие календарных признаков: Создание более сложных календарных признаков, таких как флаги праздничных/предпраздничных дней, номер квартала, для лучшего учета сезонности.
Исследование взаимодействия признаков: Поиск и создание комбинаций признаков, которые могут улучшить предсказательную силу модели.
Альтернативные модели: Применение и сравнение других алгоритмов машинного обучения (например, градиентный бустинг, случайный лес), которые были импортированы, но не описаны в финальных подходах.
Обработка данных: Более тщательная работа с пропущенными значениями и выбросами, особенно во внешних источниках данных.
